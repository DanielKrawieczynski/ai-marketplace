# Tryb NFR

1. Ustal wymagania projektu: ticket, `/.vibe/01-prd.md` (sekcja NFR), dokumentacja repo, skill `org-standards`; brak — ogólna lista z `../../sdlc-standards/references/nfr.md`.
2. Zakres: zmiany gałęzi; dla nowej aplikacji lub na prośbę — cały serwis. Sprawdź względem tej listy (wydajność, odporność, obserwowalność, konfiguracja, wdrożenie) i wymagań projektu, których zmiana dotyczy.
3. Raport wg `../../sdlc-standards/references/review-report-format.md`: dla każdego problemu sekcja NFR lub wymaganie, lokalizacja, rekomendacja; na końcu „Zestawienie” z `nfr.md`.

Po akceptacji raportu zastosuj poprawki i zacommituj wg `sdlc-standards`.
